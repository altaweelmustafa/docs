Chapter 3, Part 1 – IoT System Phases

posted on 2026 Jun 15

IoT security becomes easier to understand when the system is divided into phases. Each phase has its own role, and each role introduces possible security risks.

1. Data collection / acquisition / perception

This phase collects data from IoT devices or things.

Examples include:

  • Sensors that collect dynamic data
  • RFID tags that identify static objects
  • Chips inside vehicles or moving devices
  • Body sensors in healthcare systems

The main security idea is that the system must trust the source of the collected data. If the device is fake, compromised, or misconfigured, the whole system may make decisions based on wrong data.

2. Storage

After data is collected, it needs to be stored.

Storage may happen in:

  • Local memory on the IoT device
  • A local gateway
  • A cloud data center

Many IoT devices have limited memory and processing power, so cloud storage is often used. This makes storage easier, but it also introduces cloud-related risks such as leakage, unauthorized access, and data sovereignty concerns.

3. Intelligent processing

In this phase, the system analyzes data and provides smart services.

The processing unit may:

  • Answer user queries
  • Detect events
  • Control connected devices
  • Trigger automatic actions

The security risk here is that wrong or manipulated data can lead to wrong decisions. In critical systems such as healthcare, traffic, or factories, that can cause serious damage.

4. Data transmission

Data transmission happens between different parts of the IoT system:

  • From sensors or RFID tags to data centers
  • From storage to processing units
  • From processors to controllers, devices, or end users

This phase needs confidentiality, integrity, and authentication. Attackers may try to listen to data, modify it, replay old messages, or pretend to be a legitimate device.

5. Delivery

Delivery means sending processed data or commands to the correct destination on time.

A secure delivery process should make sure that:

  • Data reaches the intended receiver
  • Data is not changed during delivery
  • Commands are delivered on time
  • Legitimate users and devices can still access the service

Quick summary

Phase Main purpose Main security concern
Data collection Gather data from devices Fake or compromised data source
Storage Keep data locally or in the cloud Leakage, access control, data loss
Processing Analyze data and control devices Wrong decisions from manipulated data
Transmission Move data between components Eavesdropping, modification, replay
Delivery Send final result or command Delay, alteration, or wrong receiver

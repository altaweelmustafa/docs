Chapter 3, Part 2 – Phase Attacks and Data Protection

posted on 2026 Jun 15

The IoT system phases introduce different attacks. The early slides focus especially on the data perception and storage phases, where sensitive data can be exposed, lost, or modified.

Phase attacks overview

The main phase-based attack concerns are:

Phase Example threats
Data perception Data leakage, data sovereignty, data breach, authentication problems
Storage Availability attacks, access control issues, integrity attacks
Processing Authentication attacks
Transmission Channel security attacks, session hijacking, routing attacks, flooding
Delivery Human or machine misuse, attacker-controlled delivery

Data leakage or data breach

Data leakage means unauthorized data is exposed to an unintended destination.

It can be:

  • Internal or external
  • Intentional or accidental
  • Caused by hardware or software
  • Caused by weak security, misconfiguration, or malicious behavior

In IoT, leakage is dangerous because devices may collect private information such as home activity, health readings, or industrial production data.

How leakage can happen

Common causes include:

  • Weak encryption
  • Default passwords
  • Default configurations
  • Vulnerable network protocols
  • Human mistakes
  • Accidental sharing
  • Misconfigured devices or cloud services

Consequences

Possible consequences include:

  • Privacy breaches
  • Exposure of health or personal data
  • Disrupted industrial operations
  • Loss of reliability and trust
  • Business or safety impact

Countermeasures

Useful countermeasures include:

  • Encrypting data at rest
  • Regular security updates
  • Strong authentication, such as MFA
  • Network segmentation
  • Data minimization
  • User and employee awareness

Data sovereignty

Data sovereignty means that digitally stored information is subject to the laws of the country where it is stored or processed.

This matters in IoT because cloud services may store data across different countries. Organizations may not always know where their data is physically stored, which can create legal and privacy concerns.

Data loss

Data loss is different from data leakage.

  • Data leakage means data is exposed to unauthorized parties.
  • Data loss means data disappears, becomes corrupted, or becomes unavailable.

Data loss may happen because of:

  • Hardware failure
  • Software failure
  • Accidental deletion
  • Natural disasters
  • Corruption or unavailable storage

The focus for data loss is backup, recovery, and availability.

Data authentication

Data authentication checks that received data really came from the expected source and was not changed during transit.

It supports:

  • Integrity: the data was not altered
  • Originality: the data came from a legitimate device or user

This is important because IoT data may be used to control real-world actions. For example, a sensor reading may cause a machine, alarm, or actuator to respond.

Authentication can use methods such as message authentication codes, challenge-response techniques, asymmetric cryptography, and multi-factor authentication, depending on device capabilities.

IoT authentication challenges

IoT authentication is difficult because of:

  • Lack of one universal standard
  • Large numbers of devices
  • Limited processing power
  • Limited memory
  • Need for low energy consumption
  • Different vendors and protocols

A good IoT authentication solution must be scalable, lightweight, and strong enough to prevent spoofing or tampering.

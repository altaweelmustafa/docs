Which Language is the Best?

There’s no single “best” programming language. We can only say a language is more suitable for a certain application. Comparisons only really make sense within similar languages or similar domains, on benchmarks like speed, space usage, ease of use, available libraries, and so on.

Readability

The most important criteria of a programming language (we made these languages to be understood, after all). It’s about how easy a piece of code is to read and understand.

What contributes to readability:

  • Simplicity: a language with too many basic components is harder to learn. People tend to gravitate to just a subset of features based on personal preference. Example: while/for/recursion all exist, but everyone has their favorite. Same with x=x+1, x+=1, x++, ++x, multiple ways to do the same thing.

  • Orthogonality: the symmetry of relationships among the primitives that combine to form language constructs. The language shouldn’t behave differently in different contexts.

    • Example: in Pascal, loop blocks must use BEGIN...END, except the REPEAT...UNTIL statement, which breaks that pattern.
    • Example: on IBM mainframe, A Reg1,mem works but AR Reg1,Reg2 is a separate instruction for register-to-register addition.
    • VAX, by contrast, has just one Add op1,op2 instruction for all operand types (memory or register), making it more orthogonal.

    The less orthogonality, the more instructions there are. The more orthogonality, the more problems for the compiler.

  • Control Structures: early languages like FORTRAN and COBOL had very limited control structures (COBOL only had the for loop), which pushed people toward heavy goto usage and hurt readability. Block-structured programming in the 70s fixed this.

  • Data Types and Structures: a missing or unclear data type can hurt readability. Pascal has a real Boolean type:

    flag:Boolean;
...
flag:=true;
if flag then ...

    C has no boolean type, so a flag is usually faked with an int:

    int flag;
flag = 1;
...
if(flag) ...

  • Syntax Considerations: identifier length, separators, and use of keywords (like BEGIN/END) in compound statements all factor in too.

Writability

The ability to write programs in a language. Closely tied to readability, the same factors that make a language readable tend to make it writable.

Writability should be compared within the same domain. COBOL isn’t suited for scientific programs, ALGOL60 is. Similarly, ALGOL60 isn’t a great fit for AI work compared to PROLOG.

Reliability

How much we can “trust” a language to perform well under all conditions. Affected by:

  • Type Checking: verifying that operands of an operation have compatible types
  • Exception Handling: the ability to detect an error, report it, and recover from it
  • Aliasing: having two or more distinct names referencing the same memory location

Cost

Cost Type What It Depends On
Programmer Training Simplicity and orthogonality
Software Creation Writability
Compilation Time/processing power/space needed to compile
Execution Time/processing power/space needed to run
Compiler Development Building the compiler itself
Maintenance Readability

Other Factors

  • Portability: can the program move and run on a different platform? A big plus.
  • Generality: is the language general purpose, usable for everything?
  • Efficiency: covers three areas
    • Efficiency in translation
    • Efficiency in execution
    • Efficiency in writing programs

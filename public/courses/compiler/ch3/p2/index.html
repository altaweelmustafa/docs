Runtime Environment

The space allocation for programs and data in memory during execution.

There are 3 types:

1. Fully-Static Environment

All properties of the language are predetermined before execution. Address allocation happens when the code is loaded, not when it runs.

FORTRAN is the classic example. All variable memory locations are fixed during execution. FORTRAN also only has one type of procedure, the subroutine, and subroutines can’t be nested. This also rules out recursion. So the original FORTRAN fits a fully-static environment well.

2. Fully-Dynamic Environment

Better suited for dynamically computed procedures, like LISP. Works best with functional and logical programming, since it allows recursive function calls through dynamic allocation.

3. Stack-Based Environment

A hybrid of the two above. Static allocation handles variables and data structures, while a stack handles recursion, nested functions, and procedures during execution. This is the most common scheme today.

Used in block-structured (imperative/procedural) languages: ALGOL-like languages including Pascal, C, Modula, Ada, etc.

General rule of thumb:

  • Languages with strong static structure tend to be compiled (imperative languages)
  • Languages with more dynamic structure tend to be interpreted (functional, logical languages)

Error Detection and Recovery

There’s always a trade-off between speed and robustness in error handling. Faster error handling tends to be less robust, while more complex error handling makes debugging easier at the cost of processing power and time.

4 Types of Errors

Type Description When Detected
Lexical Illegal character detected (e.g. # in C) During Lexical Analysis. Easiest to find and fix.
Syntax Grammar/production rule violation (e.g. missing semicolon) During Syntax Analysis. A bit harder, still manageable.
Semantic Split into static and dynamic See below
Logical Mismatch between what the programmer meant and what the code actually does Hardest to fix, purely human error

Semantic errors break down further:

  • Static: caught before execution (e.g. type mismatch)
  • Dynamic: only caught during execution (e.g. division by zero)

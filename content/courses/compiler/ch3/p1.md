# Chapter 3 - Programming Languages Principles
## Part 1: Language Translation, Compilers & Interpreters

---

## Language Translation History

Early programmers used **Machine Language**, the language of numbers. Programs were written in HEX, then translated automatically to binary.

```
2 4 63
3 4 46
5 4 57
```

Later came **Assembly**, which just gave mnemonics to machine language instructions. In compiler construction, there's no real difference between Assembly and Machine Language. The hex program above becomes:

```assembly
LOD 4,X
ADD 4,Y
STO 4,Z
```

Assuming 4 is a register, this means:
- Load the contents of memory location 63 (named X) into register 4
- Add the value at memory location 46 (named Y) to register 4
- Store the result from register 4 into memory location 57 (named Z)

This was still hard to work with, so **High Level Languages** came next: Pascal, Basic, ADA, C, and so on. With high level languages came the need for **Translators**.

---

## What is a Translator?

> A translator is an algorithm that translates source code into target code.

- Source = assembly, target = machine language -> the translator is an **Assembler**
- Source = high-level language, target = assembly or machine language -> the translator is a **Compiler**

---

## Compilers

> A compiler is an algorithm that translates a high level language program into an assembly or machine language program.

**Compilation and execution process (C example):**

```
Source Code (*.c) -> Compiler (gcc) -> Object Code (*.obj) -> Executable Code (*.bin) -> Output Data
```
(Library linking and input data feed in along the way)

A compiler generates **Object Code (Machine Code)**.

| Advantages | Disadvantages |
|------------|----------------|
| Generates object code | Complex and hard to implement |
| Faster program execution | Not portable |

---

## Interpreters

> An interpreter is an algorithm that translates source code into intermediate code, which is then executed by another algorithm with input data to produce output.

**General process:**
```
Source Code -> Interpreter -> Intermediate Code -> Another Algorithm -> Output Data
```

**Example:** converting infix to postfix and then evaluating it.
```
Infix Code -> Translator Converter -> Postfix Code -> Some Program -> Result
```

**Java example:**
```
*.java -> Java Compiler -> Byte Code -> JVM -> Result
```

| Advantages | Disadvantages |
|------------|----------------|
| Generates portable intermediate code | Slower |
| Easier to implement | |

---

## Shared Steps Between Compilers and Interpreters

Both perform the same core steps:

1. **Lexical Analysis (Scanner)**: groups characters into **Tokens**. Only catches illegal character errors.
2. **Syntax Analysis (Parser)**: groups tokens into syntax structures.
3. **Semantic Analysis**: gives the syntax structures meaning. The hardest task of the three.
4. **Code Generation**: compilers produce object code, interpreters produce intermediate code. This is where they differ.

Even though this looks like a strict pipeline, in practice these steps aren't fully independent. Almost all modern compilers are **one-pass compilers**, meaning these stages happen together rather than as separate sequential passes.

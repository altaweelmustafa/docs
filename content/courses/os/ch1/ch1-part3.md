## Operating-System Operations

### Interrupt-Driven Operation

Modern operating systems are **interrupt-driven**. If there are no processes to execute and no I/O devices to service, the OS waits for something to happen. Events are signaled via interrupts (hardware) or **traps/exceptions** (software).

A **trap** (or exception) is a software-generated interrupt caused by:
- An error (division by zero, invalid memory access).
- A specific request from a user program — a **system call**.

### Dual-Mode Operation

To protect the OS from errant user programs (and user programs from each other), hardware provides at least two modes:

| Mode | Also Called | Privileges |
|---|---|---|
| **User mode** | Mode bit = 1 | Restricted — cannot execute privileged instructions |
| **Kernel mode** | Monitor mode / supervisor mode (Mode bit = 0) | Full access to hardware and all instructions |

**Privileged instructions** (e.g., I/O control, interrupt management, timer manipulation) can only execute in kernel mode. Attempting them in user mode triggers a hardware trap.

**Lifecycle of a system call:**

1. User process invokes a system call (trap to kernel mode).
2. Mode bit flips to 0 (kernel mode).
3. OS executes the requested service.
4. Mode bit flips back to 1 (user mode); control returns to user process.

### Timer

The OS uses a **timer** to prevent a user program from running forever and never returning control. The timer generates an interrupt after a specified period.

- The OS sets the timer before scheduling a user process.
- When the timer fires, control returns to the OS.
- The OS then decides whether to continue or terminate the process.
- Timer instructions are **privileged** so users cannot manipulate them.

## Process Management

A **process** is a program in execution — it is the unit of work in a system. A program is a passive entity (a file on disk); a process is an active entity (it has a program counter, stack, heap, and data section).

### Single-threaded vs. Multi-threaded

- **Single-threaded process**: one program counter — executes instructions sequentially.
- **Multi-threaded process**: one program counter per thread — multiple sequences of instructions executing concurrently.

### OS Responsibilities for Processes

The OS is responsible for:

1. **Creating and deleting** both user and system processes.
2. **Scheduling** processes and threads on CPUs.
3. **Suspending and resuming** processes.
4. Providing mechanisms for **process synchronization**.
5. Providing mechanisms for **inter-process communication (IPC)**.
6. Providing mechanisms for **deadlock handling**.

> All these processes execute concurrently on one or more CPUs by multiplexing the CPU among them.

## Memory Management

**Main memory** is central to all modern computer operation. It is the only large storage area the CPU can access directly (along with registers and cache).

### Why Memory Management Matters

- CPU can only execute instructions loaded in main memory.
- For a program to be executed, it must be mapped to absolute addresses and loaded into memory.
- Multiple programs may reside in memory simultaneously → the OS must manage allocation.

### OS Responsibilities for Memory

1. Keeping track of **which parts of memory are currently being used** and by whom.
2. **Deciding which processes and data to move** into and out of memory.
3. **Allocating and deallocating** memory space as needed.

### Key Concepts

| Concept | Description |
|---|---|
| **Logical address** | Address generated by the CPU (virtual address) |
| **Physical address** | Actual address seen by memory hardware |
| **MMU** | Memory Management Unit — hardware that maps logical → physical addresses |
| **Swapping** | Moving entire processes between memory and disk when memory is full |
| **Virtual memory** | Allows execution of processes larger than physical memory by swapping pages/segments |

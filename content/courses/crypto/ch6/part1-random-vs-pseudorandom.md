## Where random numbers are used

A number of network security algorithms and protocols rely on random binary numbers:

- **Key distribution and mutual authentication** — nonces used for handshaking, to frustrate an opponent guessing or replaying an obsolete transaction.
- **Session key generation** — short-lived symmetric keys generated per transaction.
- **RSA key generation** (public-key cryptography, later in the course).
- **Bit-stream generation for symmetric stream encryption** (this chapter).

These applications give rise to **two distinct, not necessarily compatible** requirements: **randomness** and **unpredictability**.

---

## Randomness

Two criteria validate that a sequence of numbers is statistically random:

- **Uniform distribution** — ones and zeros occur with approximately equal frequency.
- **Independence** — no subsequence can be inferred from the others.

There are well-defined statistical tests for matching a distribution like uniformity, but there's no test that directly *proves* independence — instead, a battery of tests is applied, and if none of them can show the sequence is *not* independent, confidence grows that it is.

---

## Unpredictability

For applications like mutual authentication, session-key generation, and stream ciphers, statistical randomness alone isn't enough — **successive members of the sequence must also be unpredictable**. With genuinely random ("true") sequences, each number is statistically independent of the others and therefore unpredictable by construction. But true random numbers have practical limitations (notably inefficiency), so it's more common to use algorithms that *appear* random — in which case care must be taken that an opponent cannot predict future values from earlier ones.

**Pseudorandom numbers**: cryptographic applications typically use deterministic algorithms for number generation. Being deterministic, their output is not *actually* statistically random — but if the algorithm is good, the output passes many randomness tests anyway, and is called pseudorandom.

---

## True vs. pseudorandom number generators

### True Random Number Generator (TRNG)

Takes as input a source that is effectively random — an **entropy source** drawn from the computer's physical environment: keystroke timing, disk electrical activity, mouse movement, instantaneous clock values, etc. This source (or combination of sources) feeds an algorithm that produces random binary output; a TRNG may be a simple analog-to-binary conversion, or may need additional processing to remove bias from the source.

### Pseudorandom Number Generator (PRNG) / Pseudorandom Function (PRF)

A PRNG takes a fixed input value, the **seed** (often itself generated by a TRNG), and produces an output bit sequence via a deterministic algorithm. Because the output is determined solely by the input, **an adversary who knows the algorithm and the seed can reproduce the entire bit stream** — which is exactly why the seed must be kept secret and unpredictable.

- **PRNG** — produces an *open-ended* sequence of bits; common application: input to a symmetric stream cipher.
- **PRF** — produces a pseudorandom string of *fixed* length (e.g., symmetric keys, nonces), typically from a seed plus context-specific input (a user ID, application ID, etc).

Other than output length, there's no real difference between a PRNG and a PRF — the same algorithms serve both purposes.

### Comparison

| | PRNG | TRNG |
|---|---|---|
| Efficiency | Very efficient | Generally inefficient |
| Determinism | Deterministic | Nondeterministic |
| Periodicity | Periodic (eventually repeats) | Aperiodic |

PRNGs' periodicity is rarely desirable, but modern PRNGs have periods so long it's practically irrelevant. TRNGs can't reliably keep up with applications needing millions of random bits per second (e.g., banking, national security) — which is precisely why PRNGs, seeded from a TRNG, are the practical default.

---

## What to remember for the exam

Randomness (uniform distribution + independence) and unpredictability are two separate requirements — a sequence can be statistically random yet still predictable if generated deterministically from a known algorithm and seed. TRNGs draw entropy from physical sources and are nondeterministic but slow; PRNGs are deterministic, fast, and periodic, and are only as secure as their seed is unpredictable. PRNG vs. PRF differ only in whether the output is open-ended or fixed-length.
